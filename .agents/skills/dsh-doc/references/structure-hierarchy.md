# Page structure and hierarchy

## Page order

Lead with the reader's task and place prerequisites before dependent steps. A fixed Summary, contents, fold, and Dev Note sequence is not required.

## Section progression

Keep the common usage path concise; link deeper detail to its owning document.

## Documentation hierarchy

Package usage belongs beside the package. Cross-package structure belongs in architecture, reusable procedures in cookbooks, and lasting decision rationale in Agent Notes. Generated references come from code.

## Small rule files

Keep agent instructions specific to their subtree and avoid repeating root rules.

## Further Exploration

Link adjacent documentation when it provides a useful next step.

## Dev Note ownership

Working hypotheses should be clearly labeled and must not imply shipped behavior.
